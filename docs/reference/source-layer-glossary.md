# Source Layer Glossary

Abstract-layer terms from the 2026-11-07 source-layer analysis. A layer is a responsibility, not a directory name. Evidence uses `file:line` citations captured at audit time; line numbers may drift as the code moves.

| 术语 | English | 定义 | file:line |
|---|---|---|---|
| 采集客户端层 | SDK Client Layer | Web/mobile/Unity/server SDKs buffer events locally, persist retry queues, generate identity/event IDs, and POST NDJSON or JSON to `/v1/batch`. | `sdks/web/src/index.ts:107`, `sdks/server/src/main/java/io/oddsmaker/sdk/Oddsmaker.java:60`, `sdks/unity/Runtime/Oddsmaker.cs:139` |
| 网关边缘接入层 | Gateway Ingress Layer | `/v1/batch` performs authentication, rate limiting, schema validation, unknown-event filtering, PII sanitization, idempotency, deterministic sampling, block checks, then publishes Avro to Kafka or rejects into the DLQ. | `services/gateway-service/src/main/java/io/oddsmaker/gateway/api/BatchController.java:98`, `services/gateway-service/src/main/java/io/oddsmaker/gateway/api/BatchController.java:156`, `services/gateway-service/src/main/java/io/oddsmaker/gateway/api/BatchController.java:276`, `services/gateway-service/src/main/java/io/oddsmaker/gateway/kafka/DlqPublisher.java:41` |
| 消息传输层 | Message Transport Layer | Kafka carries `events_raw`, `risk_events`, `identity_events`, and `deadletter`; Apicurio serializes ingestion events as Avro. | `docker-compose.quickstart.yml:93`, `services/gateway-service/src/main/java/io/oddsmaker/gateway/kafka/AvroPublisher.java:72`, `services/gateway-service/src/main/java/io/oddsmaker/gateway/kafka/AvroPublisher.java:92` |
| 流处理层 | Stream Processing Layer | Seven Flink 1.19 jobs consume `events_raw` and emit ClickHouse rows, PostgreSQL feature rows, or derived Kafka events. | `jobs/flink/events-enrich-job/src/main/java/io/oddsmaker/jobs/enrich/EventsEnrichJob.java:97`, `jobs/flink/risk-job/src/main/java/io/oddsmaker/jobs/risk/RiskJob.java:148`, `jobs/flink/identity-merge-job/src/main/java/io/oddsmaker/jobs/identity/IdentityMergeJob.java:102`, `docker-compose.yml:283` |
| 分析存储层 | Analytics Storage Layer | ClickHouse holds raw events, sessions, retention, funnels, identities, dimensions, and risk aggregates, partitioned by game, environment, and date. | `schema/sql/clickhouse/schema.sql:4`, `schema/sql/clickhouse/analytics.sql:10`, `schema/sql/clickhouse/dimensions.sql:7` |
| 元数据与控制层 | Metadata and Control Layer | Control-service owns 82 JPA entities and repositories in PostgreSQL, exposes the API surface, migrates schema with Flyway, and also queries ClickHouse for dashboards, privacy actions, risk archives, and ML scoring. | `services/control-service/src/main/java/io/oddsmaker/control/Application.java:8`, `services/control-service/src/main/resources/application.yaml:33`, `services/control-service/src/main/java/io/oddsmaker/control/service/ClickHouseClient.java:37`, `services/control-service/build.gradle.kts:36` |
| 控制面消费层 | Control Consumer Layer | Control consumes Flink outputs: risk hits become cases/blocks/reviews/webhooks, identity events become PostgreSQL links, and non-gateway dead letters become data-quality counters. | `services/control-service/src/main/java/io/oddsmaker/control/service/RiskEventConsumer.java:85`, `services/control-service/src/main/java/io/oddsmaker/control/service/IdentityConsumer.java:56`, `services/control-service/src/main/java/io/oddsmaker/control/service/DeadLetterConsumer.java:50` |
| 调度与后台执行层 | Scheduling and Background Layer | Scheduled workers reconcile data retention, evaluate alerts, process exports/erasure, retry webhooks, sync Flink status, and invoke the ML trainer. | `services/control-service/src/main/java/io/oddsmaker/control/Application.java:10`, `services/control-service/src/main/java/io/oddsmaker/control/service/RetentionEnforcementService.java:160`, `services/control-service/src/main/java/io/oddsmaker/control/service/FlinkJobService.java:288`, `services/control-service/src/main/java/io/oddsmaker/control/service/MLModelService.java:927` |
| ML 训练层 | ML Training Layer | The Python package reads ClickHouse or synthetic data, engineers features, trains churn/PLTV/risk/propensity models, and atomically writes versioned JSON artifacts. | `ml/oddsmaker_ml/cli.py:33`, `ml/oddsmaker_ml/cli.py:62`, `ml/oddsmaker_ml/artifact.py:25`, `ml/oddsmaker_ml/artifact.py:80` |
| 维度同步层 | Dimension Sync Layer | A standalone agent polls CSV, Excel, JDBC, or Kafka sources; Control can also HTTP-pull pages; both normalize changes into dimension events sent through `/v1/batch`, while Flink writes item and level dimensions. | `agents/dimension-sync-agent/src/main/java/io/oddsmaker/agent/AgentMain.java:104`, `agents/dimension-sync-agent/src/main/java/io/oddsmaker/agent/GatewaySink.java:49`, `services/control-service/src/main/java/io/oddsmaker/control/service/DimensionPullService.java:229`, `jobs/flink/dimension-sync-job/src/main/java/io/oddsmaker/jobs/dimension/DimensionSyncJob.java:110` |
| 观测与运维层 | Observability and Ops Layer | Prometheus scrapes services and exporters, OTel exports traces/metrics/logs, Grafana renders dashboards, and compose/helm files define process lifecycle. | `infra/prometheus.yml:14`, `infra/otel-collector.yaml:12`, `infra/docker-compose.yml:10`, `infra/helm/oddsmaker/templates/configmap.yaml:1` |
| Web 控制台层 | Web Console Layer | The Vue SPA keeps JWT auth state, routes operational views, and calls about 120 distinct Control API endpoints through axios. | `web/src/main.js:5`, `web/src/stores/auth.js:24`, `web/src/router/index.js:6`, `web/src/services/api.js:3` |
| 共享公共层 | Shared Common Layer | Gradle libraries define the event model, HMAC signing, Kafka producer defaults, and OTel initialization; the gateway currently declares all four dependencies. | `libs/common-model/src/main/java/io/oddsmaker/common/model/Event.java:1`, `libs/common-auth/src/main/java/io/oddsmaker/common/auth/HmacSigner.java:1`, `libs/common-kafka/src/main/java/io/oddsmaker/common/kafka/KafkaProducers.java:8`, `services/gateway-service/build.gradle.kts:8` |
| 单公司边界 | Single-Company Boundary | Company identity is deployment metadata, not an event partition key; `game_id + environment` is the logical data boundary. | `services/control-service/src/main/resources/application.yaml:80`, `services/control-service/src/main/java/io/oddsmaker/control/jpa/GameEntity.java:1`, `docs/reference/architecture.md:38` |
| 存储路由 | Storage Routing | `storage_profile` records Kafka, ClickHouse, Redis, and archive targets plus isolation strategy, but only control-plane CRUD/default assignment is wired; stream and gateway connections still use deployment configuration. | `services/control-service/src/main/java/io/oddsmaker/control/jpa/StorageProfileEntity.java:30`, `services/control-service/src/main/java/io/oddsmaker/control/service/StorageProfileService.java:45`, `services/control-service/src/main/java/io/oddsmaker/control/service/GameService.java:242`, `docker-compose.yml:194` |
| 网关幂等状态 | Gateway Idempotency State | API-key context is cached in memory; signatures and logical event IDs are held in instance-local TTL maps. Multi-instance hardening explicitly names shared Redis as future work. | `services/gateway-service/src/main/java/io/oddsmaker/gateway/config/AuthService.java:109`, `services/gateway-service/src/main/java/io/oddsmaker/gateway/security/ReplayGuard.java:20`, `services/gateway-service/src/main/java/io/oddsmaker/gateway/security/ReplayGuard.java:90` |
| Flink 处理状态 | Flink Processing State | Each job uses keyed ValueState/session windows, TTL where applicable, and checkpointing; local executor containers still lack an external, recoverable state backend. | `jobs/flink/events-enrich-job/src/main/java/io/oddsmaker/jobs/enrich/EventsEnrichJob.java:88`, `jobs/flink/events-enrich-job/src/main/java/io/oddsmaker/jobs/enrich/EventsEnrichJob.java:413`, `jobs/flink/risk-job/src/main/java/io/oddsmaker/jobs/risk/RuleFetcher.java:79`, `jobs/flink/sessions-job/src/main/java/io/oddsmaker/jobs/sessions/SessionsJob.java:97` |
| 控制面规则缓存 | Control-plane Rule Cache | RiskJob polls active rules over HTTP and keeps them in an in-process atomic map; missing responses retain the last/default rules. | `jobs/flink/risk-job/src/main/java/io/oddsmaker/jobs/risk/RuleFetcher.java:16`, `jobs/flink/risk-job/src/main/java/io/oddsmaker/jobs/risk/RuleFetcher.java:78`, `jobs/flink/risk-job/src/main/java/io/oddsmaker/jobs/risk/RuleConfig.java:46` |
| 文件导出与代理状态 | File Export and Agent State | Control writes player exports to a configured directory; the dimension agent atomically stores JSON checkpoints; Unity persists event/experiment queues under its persistent data path. | `services/control-service/src/main/resources/application.yaml:126`, `services/control-service/src/main/java/io/oddsmaker/control/service/PlayerExportService.java:83`, `agents/dimension-sync-agent/src/main/java/io/oddsmaker/agent/CheckpointStore.java:34`, `sdks/unity/Runtime/Oddsmaker.cs:139` |
| 观测数据状态 | Observability Data State | Gateway keeps short-window quality counters in memory and POSTs snapshots to Control every 60 seconds for PostgreSQL persistence. | `services/gateway-service/src/main/java/io/oddsmaker/gateway/metrics/DataQualityReporter.java:42`, `services/control-service/src/main/java/io/oddsmaker/control/api/InternalDataQualityController.java:1` |
