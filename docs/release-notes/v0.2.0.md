# Oddsmaker v0.2.0 Release Notes

> 范围：P7 竞品差距收敛批次（自 v0.1.0 以来控制台可见的分析能力补齐）。总览见 `todo.md` P7 节，规划依据见 `docs/competitive-analysis.md`。

## 亮点（Highlights）

### 实时事件检视器（P7-1，Live Inspector）
- 接入期排障：Gateway 内存环形缓冲记录每条事件结局（accepted / rejected / sampled_out / duplicate），含拒绝原因与 schema 校验明细。
- 检视 API：Gateway `GET /v1/inspector/recent?game_id=&environment=&limit=&outcome=`（按 API Key 作用域过滤）；控制面代理 `GET /api/inspector/{gameId}/recent`。
- 控制台新增 Live Inspector 页（轮询刷新），事件"到没到、为什么被拒"一屏可见。

### 可复用用户分群（P7-2，Segments）
- 分群定义：属性 + 行为条件组合（单分群最多 20 个条件），支持计算、成员预览、启停、软删；成员物化到 ClickHouse `segment_members`（ReplacingMergeTree）。
- 报表注入分群过滤：在线 / 留存 / 付费漏斗 / 财务 / Crash / 风控六类报表与看板全部支持 `segment_id` 参数，控制台各报表页提供"全部分群"下拉。
- 留存分群走预聚合：`retention_daily` 新增 `subject_id` 主体维度（player>user>device，与分群物化口径对齐），成员过滤下推 ClickHouse；预聚合无历史数据时自动回退 events 实时计算（窗口钳制 90 天 + 15s 查询超时保护）。
- 权限：读 `segment:read`、写 `segment:manage`（DB 迁移 V0.9.12）。

### 自定义仪表盘 widget 化（P7-3，Dashboards）
- 仪表盘 CRUD 按游戏保存，布局 JSON 校验（widget 类型/数据源白名单、params 数值钳制、span 规范化到 12 栅格）。
- 控制台 widget 编辑器：KPI / 折线 / 柱状 / 表格 × 在线 / 留存 / 付费漏斗 / Crash 四数据源自由组合。
- 权限：读 `dashboard:read`、写 `dashboard:manage`（DB 迁移 V0.9.13）。

### 全量原始数据导出（P7-4，Raw Export）
- `events` 按日分区导出 JSONL（gzip 可选）到导出目录，分批游标读取（单分区上限 500 万行）。
- manifest 记录行数/字节/SHA-256 并原子写；分区列表 API `GET/POST /api/games/{gameId}/events-export` + 控制台导出页；对象存储由运维侧同步导出目录。
- 异步生成 + 到期清理 + 全量审计；权限复用 `export:execute`。

### 风控序列规则（PATTERN）
- 风控规则类型补齐最后一块：有序事件序列检测（如 登录→购买→退款 短时间内完成 → 疑似欺诈/脚本），至此 risk-job 七类规则（THRESHOLD / FREQUENCY / VELOCITY / RATIO / DUPLICATE_RECEIPT / AD_REWARD / PATTERN）全量上线。
- 规则在控制面按 `ruleConditions` JSON 配置序列（`"sequence": [事件名...]`，2-8 步）与 `timeWindowMinutes` 窗口，create/update 均校验；RuleFetcher 60s 内下发到 risk-job，无需重启。
- 检测为 keyed 状态机（KeyedProcessFunction + ValueState）：窗口自第一步起算、超窗惰性作废、第一步重复自动重启、命中后重置可再匹配；未引入 flink-cep 依赖，状态带 1 天 TTL 兜底回收。

### 维度同步 Agent（oddsmaker-agent）与 sync-status API
- 开源维度同步 Agent 落地：`agents/dimension-sync-agent/`（零仓库内依赖的独立 Gradle 模块，可直接部署到游戏方内网）。支持 MySQL/PostgreSQL 增量查询（单 ? 占位 + ORDER BY 水位列，水位按类型标签恢复绑定）与 CSV 目录（RFC 4180、文件粒度断点）两类 source；本地 checkpoint 原子落盘、推送成功才前进，失败自动重放（下游 ReplacingMergeTree 幂等）。
- 同步状态可观测：Agent 每轮心跳上报 Control `POST /api/dimensions/sync-status`，新增 V0.9.14 `dimension_sync_status` 表与 `dimension:read` / `dimension:manage` 权限；`GET /api/dimensions/sync-status?gameId=` 返回各 source 位点、累计推送/错误数与两口径延迟（`sinceLastPushSeconds` = Agent 存活，`sinceLastEventSeconds` = 源头新鲜度）。

### Python 训练管线（P4.4，oddsmaker-ml）
- 可训练模型落地：`ml/`（`oddsmaker-ml` Python 包，numpy/pandas/scikit-learn）为 P6 的启发式补上训练管线——churn（标签 = 快照后 14 天无事件，LR）、pltv（D7→D30 乘数过原点 WLS，w = cohort 人数）、risk（标签 = risk_actions block/review 升级处置，class_weight=balanced LR）、propensity（付费倾向，标签 = 快照后 14 天内有付费事件，特征口径与 churn 相同，LR + `PropensityScorer` 启发式基线，Java 侧同公式镜像回落）。
- 可解释优先：全部线性模型，产物为版本化 JSON（`feature_names + coefficients + intercept`，schema_version=1），Java 侧点积 + sigmoid 打分、无需 Python 运行时；每个产物自带启发式基线对照（`auc_gain_vs_heuristic` / 留出 cohort MAPE），模型相对启发式的增益可审计。
- 一键跑通：`python3 -m oddsmaker_ml train --model all --source synthetic` 种子合成数据离线全链路（数据→特征→训练→评估→产物导出），结果完全可复现；ClickHouse HTTP 真实数据入口仅依赖标准库 urllib（JSONEachRow）。
- 写回链路（Control 侧）：`POST /api/ml-artifacts` 注册版本化产物（校验语义对齐 Python `validate_artifact`，同版本重训覆盖，写审计；`ml:read / ml:manage` 权限，V0.9.15 `ml_model_artifacts` 表），`refreshChurn / refreshRiskScore / refreshPltv / refreshPropensity` 按 feature_names 取 ClickHouse 特征批量打分回写 `predictions`（TTL 30 天照旧），propensity 榜单 API 同步提供（`GET/POST /api/prediction-metrics/{gameId}/propensity[/refresh]`）。产物在场且校验通过时优先模型分（`path=model`），缺失/损坏/特征口径不匹配回落既有启发式（`path=heuristic`），两条路径以返回体与落库 `model_id / model_version` 可区分；ClickHouse 未配置诚实降级 `available=false`。
- 训练调度（Control 侧自动重训再注册）：`MLModelService.scheduledMlRetrain()`（cron 默认每日 04:20）委托 `MlRetrainScheduler`——发现已注册产物的游戏 → 触发 `python3 -m oddsmaker_ml train --model all` 子进程（数据源优先 ClickHouse 真实数据：CH 可用且 HTTP url 可推导，显式 `oddsmaker.ml.retrain.clickhouse-url` 优先否则从 JDBC url 推导；不可用时按 `allow-synthetic` 开关回落合成数据跑通）→ 产物逐个校验注册（同版本覆盖即幂等）→ 触发四类批量打分回写 predictions。周期与开关可配（`oddsmaker.ml.retrain.*`，`enabled` 默认关闭）；训练失败 / 产物非法 / 打分异常写审计（FAILURE / PARTIAL / SKIPPED，actor=`ml-retrain`）并诚实降级，不阻塞既有链路，单游戏失败不阻断其余游戏。

### Crash / 风控报表与分群贯通（P7 收尾）
- Crash 监控（Top 分组 / 趋势 / 版本崩溃率）与风控大屏（趋势 / 规则命中 / 严重等级 / 处置状态）全部支持分群过滤；版本崩溃率的分子分母子查询同时过滤，崩溃率保持在分群口径内。
- MMP 归因完成选型评估（AppsFlyer / Adjust / Airbridge，推荐"定时云存储导出 → 加载 job"方案），**有条件立项**，前置条件（任一 MMP 原始数据导出权限）未达成前不启动，详见 `docs/mmp-attribution-evaluation.md`。

## 破坏性变更（Breaking Changes）

- **ClickHouse `retention_daily` 表结构变更**：新增 `subject_id` 列并纳入排序键（SummingMergeTree 按键折叠求和，主体维度必须进键）。已有部署必须重建表迁移，迁移脚本：`schema/sql/clickhouse/migrations/2026-09-retention-daily-subject-id.sql`（一次性执行，非幂等）。
- **retention-job 与表结构强绑定**：旧版作业（5 列 INSERT）对新高维表写入会报错，新版作业（6 列 INSERT）对旧表也会报错——升级窗口内必须按"升级说明"的顺序操作。
- Control API 各报表端点新增可选参数 `segment_id`，不传时行为与旧版一致，无兼容性影响。

## 升级说明（Upgrade Notes）

1. **执行 DB 迁移**：`V0.9.12__segments.sql`、`V0.9.13__dashboards.sql`、`V0.9.14__dimension_sync_status.sql`、`V0.9.15__ml_model_artifacts.sql`（Flyway 自动应用）。
2. **执行 ClickHouse 变更**：
   - 新部署：直接导入 `schema/sql/clickhouse/analytics.sql` 与 `segments.sql` 即得新结构；
   - 已有部署：先停旧版 retention-job → 执行 `migrations/2026-09-retention-daily-subject-id.sql`（历史行 `subject_id` 置空串保留，非分群留存口径不受影响）→ 部署新版 retention-job。
3. **Flink 作业**：retention-job 需升级到与本版本配套的镜像（带 subject_id 输出）；其余作业无变更。
4. **权限**：如使用 RBAC，为需要使用的角色补授 `segment:read / segment:manage / dashboard:read / dashboard:manage / dimension:read / dimension:manage / ml:read / ml:manage`（`export:execute` 为既有权限）。
5. **导出目录**：确认控制面导出目录可写且运维同步任务（对象存储侧）就位后再开放导出页给分析师使用。
6. **训练管线（可选）**：如需使用 `ml/` 训练管线，准备 Python ≥3.10 与 `pip install numpy pandas scikit-learn`；如需自动重训调度，配置 `oddsmaker.ml.retrain.*`（`enabled=true`、cron、python-bin、ml-dir、timeout-seconds、allow-synthetic 等，默认全部关闭不启用）；不使用则无任何影响（Java/前端不依赖 Python 运行时）。

## 已知限制（Known Gaps）

- 分群报表口径：各报表的过滤键与分群成员主体口径一致（player>user>device 为主；风控报表为 user 优先），主体键不匹配时该报表返回空集属预期语义。
- Live Inspector 环形缓冲为 Gateway 进程内存态，重启即清空，仅面向接入期实时排障，不替代事件审计。
- 原始数据导出为目录落盘模式，单分区 500 万行上限；更大规模需运维侧分片。
- 留存分群实时回退路径窗口钳制 90 天；更早 cohort 的分群留存需等预聚合数据积累。
- PATTERN 序列规则单 subject 同一时刻只跟踪一条进行中序列（新序列第一步出现即以最新为起点重启）；跨序列并行组合不在此版支持范围。
- 维度同步 Agent 首版覆盖 mysql / postgres / csv 三类 source；excel/kafka source 与控制台维度同步管理页按真实接入需要再加。
- 训练管线首版仅线性可解释模型（LR / 过原点 WLS）；GBDT 精度升级、多快照时间外推验证、实时打分按需再加；自动重训调度首版为单进程串行、训练产物 version 固定（`model-version` 配置），多版本灰度切换按需再加。
