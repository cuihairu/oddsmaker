## T-DEMO502 Demo 站公网 502（todo.md:15，P1 交付面故障）

- **推荐决策**：暂缓——需用户输入（用户侧 Cloudflare DNS 与源站 TLS 面板操作）；仓内不动工。
- **理由**：
  1. 卡点事实（2026-10-28/29 复核）：经 Cloudflare=502；`curl --resolve` 直连源站 :80/:443 均 200；源站证书仍为 self-signed（`openssl s_client` Verify return code 18）。链路里坏的只剩「CF 边缘↔源站」这一段。
  2. 解锁动作全在用户面板：①CF 面板把 `oddsmaker.cuihairu.site` 的 origin A 记录改指 `106.14.216.177`（保持橙云）；②源站 443 换受信证书，或 CF SSL 模式临时改为 Full（不强校验证书）。
  3. 需账号：CF 面板与源站证书属用户私有账号/资产，agent 不硬做、也无法代做。
  4. 仓内与源站复核实测无可修项（deploy 面、control-service 容器 :38085 健康 UP、Deploy Demo 链 3 连绿）——改仓内任何东西都不影响 502。
  5. 风险：拖着不放是 P1 交付面故障持续暴露公网 502；但修复动作 5 分钟内可在用户面板完成，卡点不在工程。
- **立即执行动作**：无（记录决策）。✅ 已执行（记录决策，commit a5609c4）；**待用户**：CF 面板 origin A 记录改指 106.14.216.177（保持橙云）＋源站 443 换受信证书或 CF SSL 改 Full——均在用户私有账号面板，agent 不代做。
- **不做／延后**：不重复源站侧部署/重试（已验证无差）；等用户面板操作后按原验收复测。
- **教学**：浏览器访问走的是「你 → Cloudflare（代理）→ 你的源站服务器」。现在源站自己好好的（直连 200），但 Cloudflare 转发到源站这一跳失败（502）：一是 DNS 记录还指旧地址，二是源站用的是自签证书、CF 不认。修复只需要用户在 Cloudflare 后台改一条 DNS 记录、把 SSL 模式从「严格」调宽一档（或给源站换受信证书）。
