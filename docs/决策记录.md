## FW1016D (2026-10-16): how "ruleConditions references EventSchema fields" was landed

**Decision**: the legal value domain of a FEATURE rule's `ruleConditions.features[].feature` is the feature
registry registered on the risk-job compute side (the first 6 features of B5); unknown names are rejected
at write time. Cross-validation against EventSchema is **not** performed.

**Rationale**:
1. FEATURE conditions reference derived features of "signal × window" (`gold_gain_1h`,
   `account_count_per_ip`, …), not raw fields of the event contract (EventSchema) — cross-validating
   feature names against EventSchema is semantically unsound and would reject every legitimate
   feature rule.
2. A rule with an unknown feature name can never fire in production (the `risk_features` table has no
   such key; risk-job skips the whole rule when parsing every 60 seconds), so it used to be silently
   skipped — the same write-path discoverability gap already tightened for shape-level validation
   (scope/feature/op/value).
3. The feature-name list is produced by risk-job alone and is naturally enumerable; registering it as
   constants pinned by tests on both sides to the same documented list mirrors the existing signal
   registry (`RiskSignals` mirrored on both sides).

**Impact**:
- risk-job: adds the `RiskFeatures` source of truth; `RiskJob.buildFeatureBranch` and the `FeatureCalc`
  feature-class constructors now reference the constants (feature name values unchanged, no behavior
  change).
- control-service: adds the `service/RiskFeatures` mirror plus an unknown-name check in the FEATURE
  branch of `RiskRuleService.validateConditions` (error message contains `known feature`).
- Unchanged (compatibility-first hard rule): the `ruleConditions` JSON shape, the `rule_conditions`
  column, existing rows (the demo DB has 0 FEATURE rows — no legacy exposure), the read path
  (tolerant skip semantics of replay/RuleFetcher), and all existing metric names; the only change is
  the new write-path check.
- The two sides share no dependency module; changing the list must land on both sides in the same
  batch (each side's tests pin the same DOCUMENTED baseline).

**How to overturn**: delete `service/RiskFeatures` and the unknown-name check branch in
`validateConditions`; revert `RiskJob`/`FeatureCalc` to the string literals; remove both `RiskFeatures`
classes together with their tests, restoring shape-level validation only.

## PATROL016 (2026-10-16): docs subdirectory bilingual pairing uses same-directory sibling files, not locale mirrors

**Decision**: the 52 subdirectory pages under docs/ are paired with same-directory sibling files — a Chinese
source gets `X.en.md`, an English source gets `X.zh.md` — and both files carry a language switcher on line 3
pointing at each other; nothing is migrated to mirrored `docs/zh/` paths, the locale directories' existing
content stays untouched, and the `.vitepress` sidebars / locale config are unchanged.

**Rationale**:
1. Same-named files across the locale directories are not translations of each other:
   `docs/reference/index.md` (an English API index) and `docs/zh/reference/index.md` (a Chinese reference
   index) are independent documents; the analytics/gaming-scenarios/api-reference pairs differ by
   164/198/738 lines. Mirrored placement would collide with existing divergent content and would first
   require adjudicating which copy is canonical.
2. Sibling files match the bilingual scheme already delivered for the docs root (bea9cf1), and the pairing
   is mechanically verifiable (equal line/heading/table counts + byte-identical code blocks + symmetric
   switchers).
3. Pure-markdown change: no build config or routing touched.

**Impact**: 51 new files; each of the 51 source files gets a single inserted switcher line (`zh/index.md` was
already handled in the docs-root round, with the switcher on the first line after its front matter);
commands/paths/code blocks/proper nouns preserved verbatim. As part of docs-code reconciliation, one typo in
`06-od2-restructure-plan.md` §4.1 was also fixed in both languages: "events not carrying deprecated fields
are rejected as invalid_schema" → "events carrying deprecated fields…", aligning with §3.3.3 of the same
document and the actual schema behavior (top-level `additionalProperties: false`).

**How to overturn**: delete all the new `.en.md`/`.zh.md` files and remove the switcher lines from the
sources to restore the previous state; to move to a locale-mirror structure instead, the 4 divergent pairs
(reference/{index,analytics,gaming-scenarios,api-reference}) must first be adjudicated pair by pair.

## P1016AM (2026-10-16): the English body moves into the base name on English-locale pages (base/`.zh.md` swap)

**Decision**: the 18 pages whose base name sits in the English locale but whose body was still Chinese
(14 under subdirectories plus 4 at the docs root — competitive-analysis, mmp-attribution-evaluation,
决策记录, 审计-文档一致性) were swapped with their existing `.en.md` translations: the base name now holds
the English body and the Chinese original moved to the same-directory `.zh.md` sibling. Canonical-version
ruling: English is canonical for the English-locale slot; the Chinese original is preserved verbatim as
`.zh.md`. The divergent same-name files under `docs/zh/**` are left untouched.

**Rationale**:
1. Readers of the English site were still being served Chinese bodies on those 18 pages — the
   counterpart-language files existed but sat under a suffix no locale router points at, so the defect
   survived the pairing round.
2. Zero new translation: the `.en.md` files had already been produced and verified in the previous round
   (structure parity, byte-identical code blocks, no Chinese body residue), so this is a rename plus one
   switcher line per file.
3. After the swap the whole repo follows one uniform rule: within each locale the **base page carries that
   locale's language** (English under `docs/`, Chinese under `docs/zh/`), and the counterpart language lives
   in the same-directory sibling suffixed with the other language code (`.zh.md` / `.en.md`) — matching the
   pages that were already correct (README, index, api-reference, game-event-dictionary,
   game-analytics-redesign on the English side; all `docs/zh/**` bases on the Chinese side).
4. Fully reversible (`git mv` back) and no build config or routing touched.

**Impact**: 18 pairs renamed (36 files), switchers updated on both sides, `docs/zh/**` untouched, all other
content byte-identical. Known consequence: sibling pages such as `docs/reference/index.zh.md` keep the
internal links copied verbatim from their English source (e.g. `/reference/risk`), which now resolve to the
English page; a reader there reaches the Chinese body through the line-3 switcher. Retargeting sibling-page
internal links to the same-language counterpart is a possible follow-up, not done here.

**How to overturn**: `git mv` each `X.md`→`X.en.md` and `X.zh.md`→`X.md`, then restore the switcher lines.

## R2PATROL (2026-10-16): sibling-page internal links retargeted to the same-language counterpart

**Decision**: the follow-up deferred by P1016AM is now landed. Internal links inside sibling pages that
resolved to an opposite-language base page are retargeted to the same-language counterpart, and 4 genuinely
dead links are fixed. 16 links across 4 files; no file moves, no routing or config change.

**Rationale**:
1. Four of them were live 404s: `docs/reference/api-reference.md` and its `.zh.md` sibling both linked to
   `/reference/dimension-sync`, which has never existed under the English locale — since 9ba45f9 the
   dimension-sync design doc has lived only at `docs/zh/reference/dimension-sync.md`. It has been dead
   since that commit and stayed invisible because VitePress does not fail the build on dead internal links.
2. The remaining twelve were silent language flips: a Chinese sibling page linked straight through to the
   English base, so a Chinese reader took one extra switcher click per hop to stay in Chinese.
3. The retarget is mechanical and same-directory: `X.zh.md` links go to `X.zh`, and the dimension-sync pair
   goes to the two pages that already exist (`/zh/reference/dimension-sync` for Chinese,
   `/zh/reference/dimension-sync.en` for English). Cross-locale linking is an established convention here
   (`docs/reference/api-reference.md` already links to `/zh/reference/api`).
4. No link inside a fenced code block was touched, so the structure-parity guarantees are untouched.

**Impact**: `docs/reference/api-reference.md`, `docs/reference/api-reference.zh.md`,
`docs/reference/index.zh.md`, `docs/operations/index.zh.md`. After the fix a repo-wide scan found 0 dead
links (46 route-style + 140 relative `.md`); line/heading/table/fence counts and byte-identical code blocks
verified unchanged for the three touched pairs, switchers still symmetric. `pnpm docs:build` green.

**How to overturn**: revert the 16 link targets (one token per link). Note that reverting restores the four
404s.
