## FW1016D（2026-10-16）：「ruleConditions 引 EventSchema 字段」的落地方式

**拍板**：FEATURE 规则 `ruleConditions.features[].feature` 的合法取值域 = risk-job 计算面注册的
特征清单（B5 首批 6 特征），写路径未知名显式拒绝；**不做**与 EventSchema 的交叉校验。

**理由**：
1. FEATURE 条件引用的是「信号 × 窗口」派生特征（`gold_gain_1h`、`account_count_per_ip` 等），
   不是事件契约（EventSchema）的原始字段——对特征名做 EventSchema 交叉校验在语义上不成立，
   会把全部合法特征规则判为非法。
2. 未知名规则在生产侧永远不会命中（`risk_features` 表无此键，risk-job 每 60 秒解析时整条跳过），
   此前只能靠静默跳过兜底——与同批已收紧的形态级校验（scope/feature/op/value）同属写路径可发现性缺口。
3. 特征名清单由 risk-job 单点产出，天然可枚举；登记为常量并由两侧测试钉同一份文档名单，
   与仓内既有信号清单（`RiskSignals` 两侧镜像）同构。

**影响面**：
- risk-job：新增 `RiskFeatures` 真源，`RiskJob.buildFeatureBranch` 与 `FeatureCalc` 各特征类构造处改引常量
  （特征名取值不变，无行为变化）。
- control-service：新增 `service/RiskFeatures` 镜像 + `RiskRuleService.validateConditions` FEATURE 分支
  追加未知名校验（报错文案含 `known feature`）。
- 不变项（兼容优先硬口径）：`ruleConditions` JSON 形态、`rule_conditions` 列、存量行（演示库 0 条 FEATURE 行，
  无存量风险）、读路径（replay/RuleFetcher 容忍跳过语义）、既有指标名全部不变；变化仅新增写路径校验。
- 两侧无共享依赖模块，改名单必须两侧同批（各自测试钉同一 DOCUMENTED 基线）。

**推翻方式**：删 `service/RiskFeatures` 与 `validateConditions` 的未知名校验分支，`RiskJob`/`FeatureCalc`
回退字面量；两侧 `RiskFeatures` 及其测试一并移除，恢复形态级校验即可。

## PATROL016（2026-10-16）：docs 子目录双语配对用同目录兄弟文件而非 locale 镜像

**拍板**：docs/ 子目录 52 页的双语配对一律用同目录兄弟文件——中文源补 `X.en.md`、英文源补 `X.zh.md`，
两份顶部第 3 行互指语言切换器；不迁移到 `docs/zh/` 镜像路径、不改 locale 目录既有内容、不动
`.vitepress` 侧边栏与 locale 配置。

**理由**：
1. locale 目录下的同名文件并非互译：`docs/reference/index.md`（英文 API 索引）与 `docs/zh/reference/index.md`
   （中文参考索引）内容各自独立，analytics/gaming-scenarios/api-reference 三对差异 164/198/738 行；
   镜像放置会与既有分叉内容冲突，还须先裁断哪份为正本。
2. 兄弟文件与 docs/ 根目录已交付的双语口径（bea9cf1）一致，配对关系可机械校验
   （行数/标题/表格计数一致 + 代码块逐字节相同 + 切换器对称互指）。
3. 纯 markdown 改动，不触碰构建配置与路由。

**影响面**：51 个新文件；51 个源文件各插入 1 行切换器（另 `zh/index.md` 早已随根目录轮处理，切换器在
front matter 后首行）；命令/路径/代码块/专有名词原样保留。顺带按文档对账规则修
`06-od2-restructure-plan.md` §4.1 一处笔误：「未携带废弃字段的事件按 invalid_schema 拒」改为
「携带废弃字段…」，与同文 §3.3.3 及 schema 顶层 `additionalProperties: false` 的真实行为对齐
（中英两版同批修正）。

**推翻方式**：删全部新增 `.en.md`/`.zh.md` 文件、撤掉源文件切换器行即回原状；若要改走 locale 镜像结构，
须先对 4 对分叉文档（reference/{index,analytics,gaming-scenarios,api-reference}）逐对裁断正本。

## P1016AM（2026-10-16）：英文 locale 页把英文正文放回基名（基名 / `.zh.md` 互换）

**拍板**：基名位于英文 locale、正文却仍是中文的 18 页（子目录 14 页 + 根目录 4 页——competitive-analysis、
mmp-attribution-evaluation、决策记录、审计-文档一致性），与其已有的 `.en.md` 译版互换：基名改为英文正文，
中文原件移到同目录 `.zh.md` 兄弟。正本裁断：英文 locale 槽位以**英文为正本**，中文原件按原样保存为
`.zh.md`；`docs/zh/**` 下的同名分叉文档一律不动。

**理由**：
1. 英文站点读者此前在这 18 页上仍看到中文正文——对应语言版虽已存在，但挂在任何 locale 路由都不指向的
   后缀上，配对轮并未消除该缺陷。
2. **零新增翻译**：`.en.md` 是上一轮已产出并验真的（结构计数一致、代码块逐字节相同、正文无中文残留），
   本次只是改名 + 每文件改 1 行切换器。
3. 互换后全仓统一为一条规则：**每个 locale 内的基名页用该 locale 的语言**（`docs/` 下英文、`docs/zh/` 下中文），
   另一语言放同目录、带另一语言码后缀的兄弟文件（`.zh.md` / `.en.md`）——与本就正确的页一致
   （英文侧 README、index、api-reference、game-event-dictionary、game-analytics-redesign；中文侧 `docs/zh/**` 全部基名页）。
4. 完全可逆（`git mv` 换回），不动构建配置与路由。

**影响面**：18 对改名（36 个文件），两侧切换器同步更新，`docs/zh/**` 不动，其余内容逐字节不变。
已知副作用：`docs/reference/index.zh.md` 这类兄弟页仍保留从其英文源逐字复制的内部链接（如 `/reference/risk`），
互换后这些链接指向英文页，该处读者经第 3 行切换器抵达中文正文。把兄弟页内部链接改指同语言版本可作为后续项，
本次不做。

**推翻方式**：对每对 `git mv X.md→X.en.md`、`X.zh.md→X.md`，再还原切换器行即可。
